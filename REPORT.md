## 1. Общая информация

Сервис **Lumière Cinema** представляет собой информационную систему современного кинотеатра, обеспечивающую:
- Ведение каталога фильмов с интеграцией метаданных (хронометраж, возрастные рейтинги, постеры, оценки);
- Управление конфигурацией кинозалов (IMAX, Dolby Atmos, VIP Lounge) и посадочными местами;
- Формирование сетки сеансов с расчётом времени окончания сеанса;
- Бронирование и продажу билетов с защитой от одновременной покупки одних и тех же мест (овербукинга);
- Личный кабинет зрителя и систему отзывов/рейтингов.

В качестве реляционной СУБД выбрана **PostgreSQL 16**, а в качестве ORM-инструмента — **Prisma ORM (v6)**.

## 2. Подключение к БД и проверка соединения

### 2.1. Что было сделано:
1. **Установлены зависимости**:
   - `@prisma/client` — клиент для работы с базой данных в TypeScript/JavaScript;
   - `prisma` — консольная утилита разработчика (CLI) для генерации типов, миграций и сидирования;
   - `dotenv` — библиотека для безопасного чтения переменных окружения из файла `.env`.
2. **Созданы конфигурационные файлы**:
   - `.env.example` — эталонный файл конфигурации переменных окружения без секретных данных;
   - `.env` — файл окружения с рабочей строкой подключения `DATABASE_URL`:
     ```env
     DATABASE_URL="postgresql://postgres:postgres@localhost:5432/lumiere_db?schema=public"
     ```
   - `docker-compose.yml` — конфигурация для мгновенного поднятия официального контейнера PostgreSQL 16 Alpine локально.
3. **Создан синглтон подключения** (`src/db/prisma.ts`):
   - Реализует паттерн Singleton для пула соединений, предотвращая исчерпание дескрипторов соединений при горячей перезагрузке приложения.
4. **Разработан исполняемый скрипт проверки соединения** (`src/db/test-connection.ts`):
   - Выполняет контрольный нативный SQL-запрос через `$queryRaw`:
     ```sql
     SELECT 1 AS connected, version() AS pg_version, current_database() AS db_name, current_user AS current_user;
     ```
   - Замеряет время отклика (latency в миллисекундах);
   - Автоматически маскирует пароль в строке подключения в логах консоли;
   - В случае ошибок (например, PostgreSQL ещё не поднят) выводит код ошибки (например, `P1001`), время до таймаута и конкретные пошаговые рекомендации по устранению.
5. **Добавлена команда запуска в `package.json`**:
   ```bash
   npm run db:test
   ```

## 3. Схема Prisma, миграция и Seed

### 3.1. Схема базы данных (`prisma/schema.prisma`)
Спроектирована 3-я нормальная форма (3NF) с 10 сущностями:
- `User` — пользователи кинотеатра (email, хеш пароля, имя, фамилия, телефон, роль);
- `Role` (ENUM) — роли пользователей: `CUSTOMER`, `ADMIN`, `MANAGER`, `CASHIER`;
- `Movie` — кинофильмы (название, оригинальное название, длительность, год, постер, возрастной рейтинг);
- `Genre` — жанры фильмов (название, slug);
- `MovieGenre` — таблица связи многие-ко-многим между фильмами и жанрами с композитным первичным ключом `@@id([movieId, genreId])`;
- `Hall` — кинозалы (название, общее число мест, тип экрана, звуковая система);
- `Seat` — места в залах (номер ряда, номер места, тип: `STANDARD`, `VIP`, `ACCESSIBLE`). Установлен уникальный индекс `@@unique([hallId, row, number])`;
- `Session` — расписание показов (фильм, зал, дата/время начала и окончания, базовая стоимость, формат `FORMAT_2D`, `FORMAT_3D`, `FORMAT_IMAX`, статус);
- `Booking` — заказы билетов (уникальный номер бронирования, контакты покупателя, статус оплаты, сумма);
- `BookingSeat` — конкретные выкупленные кресла с ценой билета. **Ключевое ограничение**: `@@unique([sessionId, seatId])`, аппаратно блокирующее продажу одного кресла двум разным клиентам на один сеанс;
- `Review` — отзывы зрителей с оценкой от 1 до 5 и текстом рецензии.

### 3.2. Миграция инициализации (`prisma/migrations/0_init/migration.sql`)
Создан чистый SQL-скрипт, содержащий:
- Создание 6 перечислений (`CREATE TYPE ... AS ENUM`);
- Создание 10 таблиц со строгой типизацией данных (`TIMESTAMP(3)`, `DECIMAL(10,2)`, `INTEGER`, `TEXT`);
- Наложение первичных ключей (`PRIMARY KEY`), уникальных индексов (`UNIQUE INDEX`) и оптимизирующих B-Tree индексов для внешних ключей;
- Внешние ключи (`FOREIGN KEY`) с каскадными политиками `ON DELETE CASCADE` и `ON DELETE RESTRICT` для целостности расписания.

## 4. Описание API и RBAC

Подробная спецификация вынесена в файл `docs/API_SPECIFICATION.md`. Ниже приведены ключевые моменты:

### 4.1. Ролевая модель (RBAC)
Выделено 5 ролей пользователей:
1. `Guest (Public)` — публичный доступ без авторизации;
2. `Customer` — авторизованный покупатель билетов;
3. `Cashier` — сотрудник кассы кинотеатра;
4. `Manager` — менеджер репертуара и модератор отзывов;
5. `Admin` — главный администратор с неограниченными правами.

### 4.2. Перечень маршрутов API:
| Метод | Маршрут | Роли доступа | Описание |
| :--- | :--- | :--- | :--- |
| `POST` | `/api/v1/auth/register` | `Guest` | Регистрация нового зрителя |
| `POST` | `/api/v1/auth/login` | `Guest` | Вход по логину/паролю, получение JWT |
| `GET` | `/api/v1/auth/me` | `Customer`, `Cashier`, `Manager`, `Admin` | Получение профиля текущего пользователя |
| `GET` | `/api/v1/movies` | `Guest` (Public) | Каталог фильмов с фильтрацией по жанрам и поиском |
| `GET` | `/api/v1/movies/:id` | `Guest` (Public) | Детальная страница фильма, отзывы и сеансы |
| `POST` | `/api/v1/movies` | `Manager`, `Admin` | Добавление фильма в каталог |
| `DELETE` | `/api/v1/movies/:id` | `Admin` | Удаление фильма из репертуара |
| `GET` | `/api/v1/genres` | `Guest` (Public) | Список доступных жанров |
| `GET` | `/api/v1/halls` | `Guest` (Public) | Список залов и их оборудования |
| `GET` | `/api/v1/halls/:id/seats` | `Guest` (Public) | Схема расположения кресел в зале |
| `GET` | `/api/v1/sessions` | `Guest` (Public) | Расписание сеансов по датам и залам |
| `GET` | `/api/v1/sessions/:id/seats-availability` | `Guest` (Public) | Статус занятости мест на сеанс в реальном времени |
| `POST` | `/api/v1/sessions` | `Manager`, `Admin` | Назначение нового сеанса в сетку |
| `POST` | `/api/v1/bookings` | `Customer`, `Cashier` | Бронирование билетов с защитой от двойной покупки |
| `GET` | `/api/v1/bookings/my` | `Customer` | Просмотр истории собственных билетов |
| `GET` | `/api/v1/bookings/verify/:code` | `Cashier`, `Manager`, `Admin` | Сканирование и валидация билета по QR/коду |
| `POST` | `/api/v1/bookings/:id/confirm-payment` | `Cashier`, `Admin` | Подтверждение оплаты билетов |
| `POST` | `/api/v1/bookings/:id/cancel` | `Customer`, `Cashier`, `Admin` | Отмена бронирования и возврат мест в продажу |
| `GET` | `/api/v1/movies/:id/reviews` | `Guest` (Public) | Список отзывов о фильме |
| `POST` | `/api/v1/movies/:id/reviews` | `Customer` | Публикация отзыва и оценки (1..5) |
| `PATCH` | `/api/v1/reviews/:id/moderate` | `Manager`, `Admin` | Модерация и публикация/скрытие отзыва |
| `GET` | `/api/health` | `Guest` (Public) | Проверка статуса сервера и связи с PostgreSQL |

## 5. Инструкция по развёртыванию и проверке (Quickstart)

Для проверки работы проекта выполните следующие шаги:

### Шаг 1. Запуск PostgreSQL
Если у вас установлен Docker, поднимите базу одной командой:
```bash
docker compose up -d
```
*Либо укажите параметры вашей существующей базы данных PostgreSQL в файле `.env`.*

### Шаг 2. Проверка соединения
Выполните скрипт проверки связи:
```bash
npm run db:test
```
Скрипт подключится к PostgreSQL, выполнит SQL-запрос `SELECT 1` и выведет имя базы, пользователя и версию СУБД.

### Шаг 3. Применение схемы и миграции
Примените схему к базе данных:
```bash
npx prisma migrate dev --name init
```
*Или для быстрой синхронизации без создания новых файлов миграций:*
```bash
npx prisma db push
```

### Шаг 4. Наполнение базы тестовыми данными (Seed)
Запустите команду сидирования:
```bash
npm run db:seed
```
База данных будет наполнена тестовыми пользователями, залами, фильмами, сеансами, бронированиями и отзывами.

### Шаг 5. Визуальный просмотр базы данных (Prisma Studio)
Для удобного просмотра всех таблиц и связей в браузере запустите:
```bash
npx prisma studio
```
Интерфейс откроется по адресу `http://localhost:5555`.
