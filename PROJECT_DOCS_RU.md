# 🎬 Документация проекта: Премиальный Кинотеатр «Lumière»

Добро пожаловать в проект цифрового кинотеатра нового поколения **Lumière** — высокотехнологичное, отзывчивое и визуально выверенное веб-приложение для просмотра расписания фильмов, онлайн-бронирования мест и администрирования кинозалов.

В данном документе описана архитектура приложения, механизмы хранения данных, интеграция с внешними сервисами и инструкции по управлению проектом.

---

## 🚀 1. Обзор Системы

**Lumière** представляет собой интерактивную SPA-платформу на стеке **React + Tailwind CSS + Vite**, сфокусированную на эстетике темного интерфейса, плавной анимации переходов и отзывчивом пользовательском опыте на любых устройствах.

### Основные возможности (User-facing):
- **Интерактивный Живой Слайдер (Hero Carousel)**: Динамический промо-блок на главной странице, собирающий данные о лучших фильмах в прокате с кастомными промо-тегами («Выбор критиков», «IMAX Laser» и др.).
- **Каталог Фильмов**: Поиск в реальном времени, фильтрация по жанрам, датам сеансов и сортировка (по рейтингу, году выхода, алфавиту).
- **Интерактивное Бронирование мест**: Сетка залов Lounge (VIP) и Стандарт с возможностью выбора мест, динамическим расчетом стоимости (с учетом VIP-множителей и времени сеанса).
- **Личный Кабинет клиента**: Управление авторизацией, просмотр активных и архивных билетов, написание текстовых отзывов и выставление звездных рейтингов.

### Возможности Управления (Admin-facing):
- **Гибкий Планировщик сеансов**: Создание и удаление киносеансов с детальной привязкой к датам, залам, времени и цене.
- **Интеграция с TMDB API**: Поиск абсолютно любых фильмов в глобальной базе TMDB прямо из админки и их мгновенный импорт в один клик.
- **Интегрированное управление прокатом**: Управление активным кинокаталогом, включая снятие фильма с проката с каскадным аннулированием связанных сеансов.

## 🛠️ 2. Архитектурная Спецификация и Стек

- **Frontend core**: React 18+ (функциональные компоненты, хуки React).
- **Стилизация**: Tailwind CSS (библиотека утилит) с интеграцией шрифта *Inter* и *Space Grotesk*. Полноценная адаптивность под мобильные, планшеты и десктопы.
- **Анимации**: `motion` из пакета `motion/react` для высокоскоростных переходов без мерцаний.
- **Иконки**: Семейство векторных иконок `lucide-react`.
- **Сборщик**: Vite.

## 💾 3. Модель Данных и State Management

Приложение спроектировано в соответствии с **Offline-First** концепцией. Все данные хранятся и синхронизируются в локальном хранилище браузера (`localStorage`):

1. **Фильмы (`lumiere_movies`)**: Массив объектов фильмов. По умолчанию инициализируется популярным списком новинок, подтягиваемым из глобального API. При удалении или ручном импорте изменения синхронизируются в реальном времени.
2. **Сеансы (`lumiere_sessions`)**: Сетка планировщика. Связана с фильмами через `movieId`. При первом запуске или ручной очистке автогенератор наполняет расписание удобными временными блоками на 7 дней вперед для всех доступных на данный момент фильмов.
3. **Бронирования (`lumiere_bookings`)**: Хранит приобретенные билеты пользователей, выбранные координаты мест и статус оплаты.
4. **Отзывы (`lumiere_reviews`)**: Текстовые обзоры пользователей с оценками, привязанные к конкретным фильмам.
5. **Залы (`lumiere_halls`)**: Конфигурация залов (Standard Hall с классической компоновкой и VIP Luxury Lounge с диванами и повышенными тарифами).

При удалении фильма в панели управления срабатывает **каскадное удаление (cascade delete)**:
- Фильм удаляется из базы `lumiere_movies`.
- Все сеансы, привязанные к ID этого фильма, автоматически удаляются из `lumiere_sessions`.
- Это гарантирует отсутствие битых ссылок и ошибок `TypeError` на экранах выбора билетов.

## 🌐 4. Интеграция с TMDB API (The Movie Database)

Для наполнения кинотеатра живым, интересным контентом реализована полноценная интеграция с платформой **The Movie Database (TMDB)**.

Интеграция вынесена в модуль `src/lib/tmdb.js`:
- Используется безопасная v4 Bearer аутентификация через специальный защищенный токен (`TMDB_READ_TOKEN`).
- **Автоматический трендинг**: На старте приложение проверяет локальное хранилище. Если каталог пуст или содержит только статические заглушки, выполняется асинхронный запрос к `/trending/movie/day` для получения ТОП-10 фильмов мира. Для них каскадно запрашиваются полные метаданные (жанры, слоганы, бюджет) через `/movie/{id}` и генерируется актуальное расписание сеансов.
- **Поиск фильмов**: В админке доступен поиск фильмов по ключевым словам. Результаты выводятся в виде интерактивной сетки с динамической блокировкой кнопок ("Импортирован", "Импорт...").

## ⚙️ 6. Команды разработки и развертывания

В корневой директории доступны стандартные npm-команды:

### Запуск в режиме разработки:
```bash
npm run dev
```
Команда запускает локальный сервер разработки. Изменения в коде мгновенно обновляют интерфейс.

### Проверка кода линтером:
```bash
npm run lint
```
Запуск статического валидатора TypeScript/React для выявления неиспользуемых переменных, синтаксических неточностей или типов.

### Продакшн-сборка:
```bash
npm run build
```
Собирает оптимизированные, минифицированные статические файлы (HTML, CSS, сжатые JS-бандлы) в готовую для публикации директорию `dist/`.

## 🌐 8. Сетевые технологии и Компьютерные сети в проекте

При защите проекта и анализе архитектуры особое внимание уделяется информационным потокам и сетевому стеку. Данное приложение является отличным примером интеграции сетевых концепций и современных веб-технологий. Ниже подробно описано сетевое взаимодействие приложения в разрезе модели OSI и сетевых протоколов.

### 👥 8.1. Сетевая модель взаимодействия «Клиент — API» (Client-to-API)
Информационный обмен приложения строится по классической архитектуре «Клиент-Сервер». Веб-приложение в браузере пользователя (клиент, User Agent) взаимодействует с удаленным облачным сервером **TMDB API** по защищенному протоколу **HTTPS**.

С точки зрения семиуровневой **модели OSI**, данный процесс охватывает следующие этапы:
1. **Прикладной уровень (Application Layer)**: Браузер генерирует запросы `GET` с помощью JS-интерфейса `Fetch API`.
2. **Представительский уровень (Presentation Layer)**: Осуществляется SSL/TLS шифрование со стороны веб-клиента и серверов API для безопасности передаваемых данных.
3. **Транспортный уровень (Transport Layer)**: Данные инкапсулируются в сегменты протокола **TCP**, гарантирующего надежную доставку пакетов, контроль целостности и предотвращение перегрузки сети.
   - **Установление сессии (TCP 3-Way Handshake)**: Перед началом обмена данными клиент и удаленный хост TMDB выполняют трехэтапное согласование: `SYN` (от клиента), `SYN-ACK` (от сервера) и `ACK` (от клиента).
   - **Установление TLS-сессии**: Поверх TCP-соединения выполняется TLS-рукопожатие: согласование поддерживаемых алгоритмов шифрования (Cipher Suites Exchange), обмен ключами Диффи-Хеллмана/RSA и аутентификация сервера через сертификаты X.509.

---

### 📡 8.2. Протокол прикладного уровня HTTP и архитектурный стиль REST
Взаимодействие построено по канонам веб-архитектуры **REST API (Representational State Transfer)**:
- **Типы запросов & Headers**: Клиент отправляет асинхронные HTTP-запросы (методы `GET`) по URI-идентификаторам ресурсов (например, `/trending/movie/day`, `/movie/{id}`).
- **Заголовки авторизации**: Для защиты сетевого трафика и авторизации запросов в служебных заголовках HTTP (Headers) передается токен доступа по протоколу **Bearer JWT (JSON Web Token)**:
  `Authorization: Bearer <TMDB_READ_TOKEN>`.
- **Сериализация данных**: Тело ответа от сервера передается в текстовом формате прикладного уровня **JSON**, который затем десериализуется в нативные JavaScript-объекты.

---

### ⏳ 8.3. Асинхронность и неблокирующий сетевой ввод-вывод (Async/Await)
Сетевые транзакции выполняются асинхронно с применением концепции неблокирующего ввода-вывода (Non-blocking I/O) и механизма **JS Event Loop**:
- Сетевые вызовы выносятся за рамки основного потока выполнения интерфейса (браузерных вычислений) во внешние Web API. Кнопки интерфейса и анимации остаются отзывчивыми (отсутствует блокировка UI), пока пакеты данных передаются по физическим каналам связи.
- Конструкция `async/await` управляет промисами (Promises), предотвращая блокировку и упорядочивая асинхронную обработку сетевых ошибок (например, таймауты или `Status Code: 401/404/500`).

---

### 🛡️ 8.4. Оптимизация WAN-трафика и Локальное Кэширование (LocalStorage)
С целью минимизации нагрузки на внешние сетевые каналы (WAN), снижения трафика и повышения отказоустойчивости применяется интеллектуальное **локальное кэширование**:
- Локальное хранилище **LocalStorage** в рамках Same-Origin Policy браузера выступает в качестве локального сетевого кэша.
- На старте приложение сначала проверяет наличие данных в локальном кэше. Если данные валидны и расписание актуально, повторные дорогостоящие запросы по глобальной сети к серверам TMDB не отправляются.
- **Оптимизация RTT (Round Trip Time)**: Такой подход сокращает RRTT (эффективный круговой путь прохождения сигнала) до 0 миллисекунд для локальных операций, экономя пропускную способность пользовательского веб-канала и обеспечивая мгновенный отклик интерфейса даже при медленном или нестабильном соединении.

---

### ☁️ 8.5. Сетевая инфраструктура развертывания и Проксирование
Приложение подготовлено к стабильной работе в современных распределенных сетях:
- **Сетевое окружение и Порт 3000**: При запуске в контейнере приложение биндится на сетевой интерфейс `0.0.0.0` (слушать на всех сетевых картах) на стандартном порту `3000`.
- **Nginx Reverse Proxy**: Сетевой трафик, приходящий из глобальной WAN-сети, поступает на инверсный прокси-сервер **Nginx**, который осуществляет:
  1. Маршрутизацию входящих сетевых пакетов по доменному имени.
  2. Терминирование TLS/SSL (клиент общается по HTTPS с Nginx, а Nginx проксирует чистый HTTP на порт 3000 в локальную сеть контейнера для минимизации задержек).
  3. Балансировку нагрузки внешней сети и защиту сетевого контура контейнера от несанкционированного сканирования портов.
